KEY DESIGN DECISIONS:

  Decision                    Reasoning
  ────────────────────────    ──────────────────────────────────────────────────
  Two-service split           Node.js for I/O routing + MongoDB; Python for ML
  Express as gateway          Single CORS origin, centralized validation
  Synchronous forwarding      Express forwards to FastAPI (30s timeout)
  Model loaded at startup     PyTorch models loaded once; health endpoint reports
  Memory-efficient inference  Models loaded one at a time (~500MB vs 2.5GB+)
  Plugin architecture         BaseModule ABC allows adding new modules easily

2. USER FLOW — DASHBOARD (SCAN TYPE SELECTION)
--------------------------------------------------------------------------------

The dashboard presents two scan-type buttons:

  ┌──────────────────┐  ┌──────────────────┐
  │  Brain MRI       │  │  Chest X-ray     │   <-- User selects scan type
  │  (active/cyan)   │  │  (inactive/gray) │
  └──────────────────┘  └──────────────────┘

  ┌──────────────────────────────────────────┐
  │    Upload Image Area (JPEG/PNG)          │
  └──────────────────────────────────────────┘

  ┌──────────────────────────────────────────┐
  │        [  ANALYZE SCAN  ]                │
  └──────────────────────────────────────────┘

REQUEST FLOW AFTER "ANALYZE SCAN":

  1. User selects module: "brain_mri" or "chest_xray"
  2. User uploads image and clicks "Analyze Scan"
  3. Two parallel API calls fire:
     - POST /report?module={selectedModule}   (body: image FormData)
     - POST /gradcam?module={selectedModule}  (body: image FormData)
  4. Vite dev proxy routes both to FastAPI (localhost:8000)
  5. FastAPI validates image -> looks up module in registry
  6. Module runs: preprocess -> ensemble inference -> Grad-CAM -> report
  7. Results returned to dashboard:
     - Prediction label (e.g., "Glioma" or "Pneumonia")
     - Confidence percentage
     - Risk Level (High / Medium / Low)
     - Grad-CAM heatmap (hidden for "No Tumor" / "Normal")
     - AI Summary + Clinical Recommendation
     - Probability distribution bars
     - Medical disclaimer

3. ML PIPELINE ARCHITECTURE — STACKING ENSEMBLE
--------------------------------------------------------------------------------

SHARED PREPROCESSING (BOTH MODULES):

  Input: Raw image bytes (JPEG/PNG)
    |
    v
  1. PIL.Image.open() + verify integrity
  2. Convert to RGB (grayscale -> 3ch, RGBA -> drop alpha)
  3. Resize 224x224 (bilinear interpolation)
  4. Normalize: pixels / 255.0
  5. ImageNet standardization:
     normalized = (pixel - mean) / std
     mean = [0.485, 0.456, 0.406]
     std  = [0.229, 0.224, 0.225]
  6. Channels-first: (H,W,C) -> (C,H,W)
  7. Add batch dim: (C,H,W) -> (1,C,H,W)
    |
    v
  Output: PyTorch tensor [1, 3, 224, 224] float32

ENSEMBLE PIPELINE (BRAIN MRI — 4 MODELS):

6. PLUGIN ARCHITECTURE (MODULE ENGINE)
--------------------------------------------------------------------------------

  BaseModule (Abstract Base Class)
  ├── module_id        -> "brain_mri" / "chest_xray"
  ├── display_name     -> "Brain MRI Tumor Classification"
  ├── classes          -> ["Glioma", ...] / ["Normal", ...]
  ├── models_dir       -> settings.MODELS_DIR / CHEST_DIR
  ├── predict(bytes)   -> {prediction, confidence, probs}
  ├── gradcam(bytes)   -> {heatmap, prediction, confidence}
  ├── report(bytes)    -> {prediction, risk, summary, ...}
  └── is_available()   -> bool (model weights exist?)
         |
         |-- implements
         |
    ┌────┴────────────────────┐
    v                         v
  BrainMRIModule          ChestXrayModule
  • 4 base models          • 3 base models
  • 16-dim features        • 9-dim features
  • models/ dir            • chest/ dir
    |                         |
    └────────────┬────────────┘
                 v
         ModuleRegistry
         • init_registry() registers both modules
         • get("brain_mri") -> BrainMRIModule
         • get("chest_xray") -> ChestXrayModule

Adding a new imaging module (e.g., skin_lesion, retinal) requires:
  1. Create app/modules/{module_id}/ with module.py, metadata.json, config.py
  2. Implement BaseModule interface
  3. Register in init_registry()
  4. Place model weights in the configured directory

7. GRAD-CAM EXPLAINABILITY
--------------------------------------------------------------------------------

TARGET LAYERS PER ARCHITECTURE:

  Architecture       Target Layer              Rationale
  ────────────────   ───────────────────────   ──────────────────────────────
  EfficientNet-B0    model.blocks[-1]          Last MBConv block
  ResNet-50          model.layer4[-1]          Last residual block
  DenseNet-121       model.features[-1]        Last dense block
  VGG-16             Last nn.Conv2d (auto)     Deepest conv layer

ENSEMBLE GRAD-CAM STRATEGY:
  1. Run ensemble inference -> get final prediction
  2. Find base model whose argmax == ensemble's final class
  3. If multiple agree, pick highest-confidence one
  4. Generate Grad-CAM from that model's target layer
  5. Apply JET colormap at 40% opacity over original image
  6. Encode as base64 PNG and return to frontend

11. STACKING ENSEMBLE — HOW IT WORKS
--------------------------------------------------------------------------------

TRAINING PHASE (LEAKAGE-SAFE):

  1. Each base model outputs softmax probabilities on the test set
  2. Concatenate all model outputs:
     - Brain MRI: (1600, 4) x 4 models -> (1600, 16)
     - Chest X-ray: (N, 3) x 3 models -> (N, 9)
  3. Stratified split into meta-train (50%) / meta-test (50%)
  4. Train Logistic Regression on meta-train probabilities
  5. Evaluate on meta-test (ensemble never sees its own eval data)

INFERENCE PHASE (BACKEND):

  1. Preprocess image -> tensor [1, 3, 224, 224]
  2. Load each base model one at a time:
     - Forward pass -> softmax probabilities
     - Free model from memory (gc.collect)
  3. Concatenate all probability vectors
  4. Meta-learner predicts final class + confidence
  5. Pick agreeing base model for Grad-CAM
  6. Generate clinical report
